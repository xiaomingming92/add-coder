## 三、协作规则（契约主体）

### 3.1 触发条件表（谁先谁后）——必填

| 阶段 | 专家 | 触发条件 | 并行度 |
|------|------|---------|:---:|
| A | {专家} | {前置依赖/无依赖} | 并行/串行 |
| B | {专家} | {消费 A 产出} | 串行 |

**规则**：Lead Agent 每轮检查触发条件——满足即拉起，不满足不阻塞（等待或先做无依赖部分）。

**触发机制（平台 Subagent 调度）**：主智能体把当前任务描述与各专家 `description` 比对，命中即委派；彼此独立的任务可并发。因此每个专家的 `description` 必须与本节触发条件表对齐：

| 专家 | description 建议文案（触发匹配依据） |
|------|-----------------------------------|
| 专家 1 | “实施 {子 Plan 1}：{一句话职责}” |
| 专家 2 | “实施 {子 Plan 2}：{一句话职责}” |
| Lead | “总控：解析依赖拓扑，按触发条件委派专家，验收整合” |

### 3.1.1 依赖拓扑图（完整）——必填

```
{ASCII 依赖图：Lead 在顶，专家分叉，标注产出/消费关系与阶段}
```

**依赖关系声明**（机器可读，供 Lead 解析）：

```
依赖: {专家X} → { 专家Y产出(说明), ... }
无依赖: {专家A}, {专家B}（可立即并行）
```

### 3.2 文件边界（防冲突硬约束）——必填

| 专家 | 独占文件域 | 禁区 |
|------|-----------|------|
| {专家 1} | {路径域} | {禁改域} |
| {专家 2} | {路径域} | {禁改域} |

**仲裁**：跨边界修改必须经 Lead Agent 批准（记录仲裁事件，planKeyword=总控）。

> **隔离强度（2026-08-05 websearch 核实）**：平台支持 Subagent 在独立 git worktree 运行（隔离工作区）。默认文件边界（软隔离），高风险/大改场景升级 worktree（硬隔离）：
>
> | 模式 | 适用 | 隔离强度 |
> |------|------|---------|
> | 文件边界（默认） | 常规实施 | 软隔离（git diff 检查交叉） |
> | worktree 隔离 | 大改/高风险 | 硬隔离（独立 git worktree） |
>
> worktree 模式由 Lead Agent 判定启用。

### 3.3 审计归因（ADD-7）

| 动作 | 归因规则 |
|------|---------|
| `record_dev_operation` | 专家用自己 planKeyword 落库 |
| hook 事件 | 专家绑定的 planKeyword 写入 |
| 审计查询 | `query_audit_logs({ planKeyword: "<子Plan>" })` 分桶检索 |
| HITL 审批 | 子 Plan 级走子 Plan 审批；跨 Plan 决策走总控审批 |

### 3.4 完成判定——必填

| 专家 | 完成标志 |
|------|---------|
| {专家 1} | {可验证的完成条件} |
| Lead | {总控 checklist 全过 + DPS ≥ 80 → 白皮书/最终产物} |

### 3.5 冲突仲裁流程

```
专家 A 需要触碰专家 B 的边界文件
  → 记录请求（planKeyword=总控，action=BOUNDARY_REQUEST）
  → Lead Agent 裁决（同意/拒绝/改道）
  → 裁决结果 record_dev_operation 落库
  → 专家 A 按裁决执行
```

### 3.6 契约自身 HITL 审批配套——必填

> 契约是文档类型，不是实施 Plan——但契约变更（参与者/边界/触发条件）直接影响并行秩序，必须走 HITL 审批。

| 项 | 设计 |
|----|------|
| 审批类型 | `HitlType` 扩展 `COLLAB_CONTRACT`（与 PLAN/PLAN_REVIEW 并列） |
| 审批对象 | 契约文件 + 变更 diff（参与者/能力矩阵/文件边界/依赖拓扑） |
| 发起时机 | 契约新建 / 契约重大变更（参与者增减、边界重划、触发条件变更） |
| round 机制 | 复用 HitlRecord.round（同一契约多次变更递增 round） |
| 与子 Plan 审批关系 | 契约审批是**总控级**（planName=总控 Plan）；子 Plan 审批独立进行（互不阻塞） |
| 哨兵 | `{{magicDir}}/hitl/.tongyi-{contractName}`（复用当前 adapter 的哨兵机制） |
| 审计 | 契约审批记录入 HitlRecord（type=COLLAB_CONTRACT）→ query_audit_logs 可查 |
