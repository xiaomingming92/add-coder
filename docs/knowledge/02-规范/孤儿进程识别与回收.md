# 规范：孤儿进程族的识别、回收与自防（Ubuntu/Linux 实测）

> 来源：`add-coder` 2026-09-14 实测（`.codex` / `.qoder` 上 MCP server 残留反复出现）。
> 实现落点：`templates/core/scripts/mcp-server/shared/runtime-freshness.ts`（识别）、
> `scripts/mcp-restart-notice.ts`（回收）、`templates/core/scripts/mcp-server.ts`（自防）。
> 本文按"可移植做法"写，换语言/换被守护进程同样适用。

## 1. 症状与成因

**症状**：某个被 IDE/编辑器拉起的后台服务（本例：MCP server）在应用退出后**仍在运行**，
反复堆积；`ps` 里能看到同一逻辑服务出现 5 个进程，且它们**不属于任何还活着的父进程**。

**成因（关键）**：应用退出时通常只杀**直接子进程**。以本例的启动链为例：

```text
IDE/app
  └─ npx tsx <server>.ts        ← 应用只杀这一层
       └─ npm exec tsx …        ← 被 reparent 后仍活着
            └─ sh -c 'tsx' …
                 └─ node …/tsx/dist/cli.mjs …
                      └─ node --import tsx …（真正的服务）
```

父进程死后，**后几代会被 reparent**。Ubuntu 上注意：**reparent 目标通常不是 PID 1，
而是 `systemd --user`**（systemd 设了 child subreaper；本机实测 PID 1125），
容器环境里还可能是 `conmon` 之类的 subreaper。

> 结论：**"父进程没了"不能靠"ppid == 1"判断**，必须按"ppid 指向守护者（init/systemd/conmon）"或
> "ppid 指向的进程已不存在"来判断。

## 2. 判定：孤儿族识别算法

四步，全部只用 `ps` 一个数据源：

```text
① 全量快照：ps -eo pid=,ppid=,etimes=,args=
   （`=` 去表头；etimes 为已运行秒数，procps-ng 提供）
② 建索引：allPids = {每行 pid}；supervisors = {args 命中 (^|/)(systemd|init)(\s|$) 的 pid}
③ 族根：对目标进程集合（按 cmd 模式筛出的候选）建 pid→ppid 链，
        **ppid 不在候选集合内**的那条 = 族根
④ 判孤儿：族根满足任一即整族孤儿 →
     · root.ppid 指向 supervisors（init/systemd/conmon）
     · root.ppid 不在 allPids 里（父进程已消失）
       命中后把**整条链**（沿 ppid 反向可达的全部后代）一起标记
```

要点：

- **必须按整族传播**。链上后几代的 ppid 指向族内进程（不是守护者），单看自身 ppid 判不出来；
  只有族根能反映"启动者是否还在"。
- **必须同时看 `allPids`**：父进程可能连进程表都不在了（比 ppid==1 更常见）。
- 候选集合用 **cmd 模式**筛（例如 `\.(codex|qoder|...)/scripts/<server>\.ts`），
  不要用"进程名"筛——多实例/多 adapter 场景会把无关进程卷进来。

参考实现（TypeScript，去掉了业务字段）：

```ts
interface Proc { pid: number; ppid: number; cmd: string; orphan?: boolean }

function scan(psOutput: string): Proc[] {
  const supervisors = new Set<number>()
  const allPids = new Set<number>()
  const procs: Proc[] = []
  for (const line of psOutput.split("\n")) {
    const m = line.trim().match(/^(\d+)\s+(\d+)\s+(\d+)\s+(.*)$/)   // pid ppid etimes args
    if (!m) continue
    const pid = Number(m[1]), ppid = Number(m[2]), cmd = m[4]
    allPids.add(pid)
    if (/(^|\/)(systemd|init)(\s|$)/.test(cmd)) supervisors.add(pid)   // 含 systemd --user
    if (!isTarget(cmd)) continue                                       // 用 cmd 模式筛候选
    procs.push({ pid, ppid, cmd })
  }
  // 族根 → 整族标记
  const byPid = new Map(procs.map((p) => [p.pid, p]))
  const children = new Map<number, number[]>()
  for (const p of procs) if (byPid.has(p.ppid)) children.set(p.ppid, [...(children.get(p.ppid) ?? []), p.pid])
  for (const root of procs.filter((p) => !byPid.has(p.ppid))) {
    const parentGone = root.ppid === 1 || supervisors.has(root.ppid) || !allPids.has(root.ppid)
    if (!parentGone) continue
    const stack = [root.pid]
    while (stack.length) {
      const pid = stack.pop()!
      const node = byPid.get(pid)
      if (!node || node.orphan) continue
      node.orphan = true
      stack.push(...(children.get(pid) ?? []))
    }
  }
  return procs
}
```

等价的 bash 快查（**已实测**：对本机现役族报"无孤儿族"，对含孤儿的快照准确报出族根）：

```bash
#!/usr/bin/env bash
# 输入 = ps -eo pid=,ppid=,etimes=,args= 的快照（stdin）
PATTERN='[.](codex|qoder|claude|vscode|trae|add)/scripts/mcp-server[.]ts'
awk -v pat="$PATTERN" '
  {
    pid=$1; ppid=$2
    $1=""; $2=""; $3=""; cmd=$0
    seen[pid]=1; par[pid]=ppid; c[pid]=cmd
    if (cmd ~ pat) cand[pid]=1
  }
  END {
    for (p in cand) if (!(par[p] in cand)) root[p]=1        # 族根：ppid 不在候选集合内
    found=0
    for (r in root) {
      q=par[r]
      if (q==1 || c[q] ~ /(^|\/)(systemd|init|conmon)( |$)/ || !(q in seen)) {
        printf "孤儿族根 pid=%s ppid=%s parent=%s\n", r, q, (q in seen ? c[q] : "(父进程已消失)")
        found++
      }
    }
    if (found==0) print "无孤儿族"
  }'
```

用法与实测输出：

```console
$ ps -eo pid=,ppid=,etimes=,args= | bash orphan.sh
孤儿族根 pid=8332 ppid=1 parent=   /sbin/init
孤儿族根 pid=41234 ppid=1125 parent=   /usr/lib/systemd/systemd --user
$ ps -eo pid=,ppid=,etimes=,args= | bash orphan.sh     # 只剩现役族时
无孤儿族
```

> 注意 `awk` 里用 `[.]` 而不是 `\.`（GNU awk 会对 `\.` 报 `escape sequence treated as plain .` 的告警）。

## 3. 回收：两段式，且**只动孤儿**

```text
① 先 SIGTERM 整族（族内所有 pid，含 npx/npm/sh/node 各代）
② 等待 1~2 秒（给优雅退出机会）
③ 仍存活者 SIGKILL
④ 回收后**重新扫描**，后续逻辑只看真正活着的进程
```

安全红线：

- **禁止 `pkill -f <script>`**：会把正在服务的活进程一起杀（甚至杀掉调用者自己）。
- 只回收"判定为孤儿族"的 pid 列表；现役进程（族根的父进程还活着）**一律不动**。
- 优先用显式 pid 列表，而不是"按名字杀"；pid 在扫描与发送信号之间可能被复用，回收前可再校验一次 cmd。
- 在 CI/无人值守场景，回收要能 fail-open（回收失败不改变主流程退出码）。

## 4. 自防：被守护进程自己发现"启动者已死"

回收是兜底（清历史），**自防才是根治**（不再产生新孤儿）。极简做法：

```ts
function watchLauncher(): void {
  const launcherPid = process.ppid            // 启动时记录
  const timer = setInterval(() => {
    if (process.ppid !== launcherPid) {       // 被 reparent → 启动者已死
      console.error(`启动者已退出（ppid ${launcherPid} → ${process.ppid}），自退`)
      clearInterval(timer)
      process.exit(0)                          // stdio 对端已消失，继续活着没有意义
    }
  }, 15_000)
  timer.unref?.()                              // 不阻塞正常退出
}
```

- **不要**写成"ppid==1 就退出"：systemd 管理的服务本来就可能挂到 init/systemd 下（合法）。
  必须"启动时记录 + 变化即退"。
- 轮询周期取秒级即可（本例 15s）；开销只有一次 `getppid` 比较。
- 若服务有事件循环，也可监听 stdio 传输关闭/`EPIPE` 作为更快触发条件（本例未依赖）。

## 5. Ubuntu 实测的坑

| # | 坑 | 正确做法 |
|:-:|----|---------|
| 1 | reparent 目标是 `systemd --user`（PID≠1），只看 `ppid==1` 会漏 | 按 `comm/args` 判守护者：`(^|/)(systemd|init)(\s|$)` |
| 2 | 链上后几代 ppid 指向族内进程 | 按**整族**传播孤儿标记（见 §2 ③④） |
| 3 | 父进程已从进程表消失 | 同时用 `allPids` 判断"父进程不存在" |
| 4 | 启动链太长（npx→npm→sh→node）导致"杀了直接子进程 ≠ 服务停了" | 回收列**整族**；启动方式能减层就减层（如直接 `node` 起服务） |
| 5 | 容器环境另有 subreaper（conmon/podman） | 守护者名单加上这些名字 |
| 6 | `ps` 默认带表头、字段宽度不同 | 用 `-eo pid=,ppid=,etimes=,args=` 去表头；用正则解析而不是固定列切分 |
| 7 | 用 `pkill -f` 图省事 | 显式 pid 列表 + cmd 复核 |
| 8 | 把"僵尸进程(zombie)"与"孤儿活进程"混为一谈 | 僵尸=父进程未回收 exit status；孤儿=父进程已死、自己还活着。本规范处理**后者** |

## 6. 验收与现场自证

**单测（推荐至少这些用例，本例 18 例）**：

- 族根 ppid=1 → 整族标 orphan；族根 ppid=`systemd --user` → 同样标；
- 族根父进程正常存在 → 不标；
- 回收清单只含孤儿族（含链上各代），现役进程不在其中；
- **判定逻辑忽略孤儿**：只有孤儿时报"无运行中 server"，孤儿+现役并存时取现役那条。

**现场自证命令**：

```bash
# 1) 看族与父进程
ps -eo pid,ppid,etimes,args | grep '<server-pattern>' | grep -v grep
# 2) 看它属于哪个 systemd scope（Ubuntu 上很好用）
systemd-cgls --user-unit <scope-name>        # 例：app-org.chromium.Chromium-5950.scope
# 3) 确认父进程身份（是否守护者）
ps -o pid,comm,args -p <ppid>
```

## 7. 一句话总结

**"孤儿"不是按 ppid==1 判的，是按"族根的启动者已不存在（父进程消失或退化为 init/systemd/conmon）"判的；
判定要整族传播，回收要两段式且只动孤儿，根治要让被守护进程自己发现启动者已死并退出。**
