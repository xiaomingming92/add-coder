# 规范：文档校验层与生命周期联动

> 适用版本：0.3.31 起（Plan `add-coder-core-validation-lifecycle`）
> 状态：**契约**（新增校验判定必须遵循本文，不得另立实现）

## 1. 唯一形式判定真源

- 全部形式判定（章节、子章节、轮次、占位符、结构位禁词）读
  `templates/core/templates/*.schema.json`。
- **禁止**任何实现自解析 `*.template.md` 或硬编码章节名。历史上"hook 内联实现 + 临时脚手架自解析"
  与真源并存，形成三重真源——同一份 handoff 在不同路径得到不同结论，正是本规范要消除的形态。

## 2. 集中层与单一入口

| 部件 | 路径 | 职责 |
|------|------|------|
| 判定器 | `templates/core/validation/schema-validator.ts` | schema 驱动的形式判定；半角/全角等价（`normalizeWidth`）；锚定（`validateAnchors`）与结构位限定（`structText`） |
| 注册表 | `templates/core/validation/registry.ts` | 17 类文档 → schema 工厂；**未注册类型直接报错**（不回落通用校验） |
| 策略 | `templates/core/validation/policy.ts` | 卡位 → `advisory`/`blocking`（携带依据）；规则适用性（Rule × Hook） |
| 专司 | `templates/core/validation/validators/*.ts` | 各文档类型特有语义（schema 表达不了的部分，如 handoff 的可执行审计查询） |
| 入口 | `templates/core/validation/index.ts` | `validate({type, path, hook, mode, expectRounds, projectRoot, magicDir})` |

调用方（守卫 hook、封口判定、批量命令）**只能**走 `validate(...)`；返回结构含
`{ok, type, hook, mode, basis, schemaPath, issues[], diagnostics[]}`。

## 3. 卡位口径与规则适用性

- **写入前置**（PreToolUse）= `blocking`；**写后复检**（PostToolUse）= `advisory`；
  **收尾/验收**（Stop、SubagentStop）= `blocking`；SessionEnd / 手工批量 = `advisory`。
- 规则集（what）与适用性（where）分离：例如 `ANCHOR_MISS` 只在"写入时防劣化"的卡位算缺陷，
  收尾巡检只为诊断；`EVIDENCE_PLACEHOLDER_LEFT` 只在收尾/封口卡位算缺陷。
  未登记适用性的规则码**默认全卡位生效**（宁严不漏，避免新规则静默失效）。

## 4. 生命周期联动

```text
schema 真源 ─► core 校验层 ─┬─► 写入守卫（PreToolUse/PostToolUse，含 SearchReplace 子集）
                            ├─► 封口判定（unit-state 的 handoff 因子 = 存在 ∧ 合规）
                            └─► 批量命令 scripts/validate-docs.ts（收尾/sync 巡检）
                    留痕 ───┴─► AuditBridge（{magicDir}/reports/hook-events.jsonl，不另建通道）
```

- 同一文档从任意路径判定必须得到**同一结论**（含 issues 列表），由
  `tests/validation/batch-and-landing.test.ts` 与 `tests/hook-consistency.test.ts` 守护。
- 校验层随 `npm run generate` + `npm run sync` 分发到六个 magic 目录（`sync-magic-rules.toml` 的 `validation` 分类）。

## 5. 禁止静默降级（硬约束）

- schema 真源缺失 → **显式失败**（`ok=false` + 明确提示），不得静默放行或跳过。
- 抽层/搬运既有能力时，若目标实现少了原能力（如锚定、结构位限定），必须先补齐再替换。
- 工具容量/格式限制只能影响"怎么产出"，不得影响"产出什么规格"；任何降级必须显式登记。

## 6. 扩展一份新校验（操作顺序）

1. 加/改 `templates/core/templates/<name>.schema.json`（形式定义）；
2. 在 `registry.ts` 注册类型（未注册即报错）；
3. 若需类型特有语义，在 `validators/` 增专司并在 `TYPE_CHECKS` 挂载；
4. 补用例（正例 + 反例，含"改名 schema 判定随真源走"类断言）；
5. `npm run generate`（幂等自检）→ `npm run sync` → 重启 IDE 使运行态生效。
